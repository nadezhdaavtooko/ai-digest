# CLAUDE.md

Автоматический финансовый дайджест на Astro + Vercel. Проект курса Claude Code Basics.

## Стек

- Astro `^6.1.1` (`src/content/blog/` — статьи в markdown с frontmatter).
- Node `>=22.12.0` (из `engines` в `package.json`).
- Интеграции Astro: `@astrojs/mdx` (MDX в постах), `@astrojs/sitemap` (генерация `sitemap-index.xml` при билде), `@astrojs/rss` (RSS-фид из той же коллекции). Оптимизация изображений — `sharp` через `astro:assets`.
- SSR-адаптера пока нет — чистый статический билд. Если фаза курса потребует серверную логику, понадобится `@astrojs/vercel` и `output: 'server' | 'hybrid'` в `astro.config.mjs`.
- TypeScript strict (`astro/tsconfigs/strict` + `strictNullChecks`).
- Vercel (автодеплой на push в `main`).
- MCP: Tavily (поиск новостей), Replicate (обложки).

## Команды

- `npm run dev` — локальный сервер на `:4321`.
- `npm run build` — production-сборка.
- `npm run preview` — просмотр сборки.

## Структура статьи

Файл `src/content/blog/YYYY-MM-DD-slug.md` с frontmatter:

```yaml
---
title: Заголовок до 60 символов без точки
description: Одно предложение до 160 символов.
pubDate: YYYY-MM-DD
cover: https://replicate.delivery/...
source: https://example.com/news
tags: [налоги, законодательство]
---
```

## Редполитика

### Тематика

Финансы, налоги, законодательство и изменения, важные для бизнеса, лимиты, проверки, субсидии, льготы.

Аудитория — финансовый директор.

Назначение: помогать финансовому директору вовремя замечать важные изменения, которые могут повлиять на бизнес и финансовые решения.

### Формат

- Заголовок: до 60 символов, без точки.
- Описание: одно предложение до 160 символов.
- Тело: 300–500 слов, 2–4 абзаца.
- Источник: обязательная ссылка на первоисточник.
- Обложка: URL от Replicate, соотношение 16:9.

### Обязательные поля frontmatter

`title`, `description`, `pubDate`, `cover`, `source` — все заполнены. Stop-хук (фаза 06) блокирует публикацию, если хоть одно поле пустое.

## Content Style

- Тон: разговорный и понятный, без панибратства.
- Лицо: первое лицо множественного числа («мы»).
- Максимальный объём: 500 слов.
- Без маркетинговых формулировок.
- Без эмодзи.
- Язык — русский.
- Предложения до 25 слов.
- Без шаблона «от X до Y» — перечислять конкретно.
- Без AI-маркеров: «погружаться», «ландшафт», «ключевой момент», «является свидетельством».

## Digest Pipeline

Целевая архитектура автоматического пайплайна дайджеста (зафиксирована как будущие требования; в ПР-1 реализованы только контракты и локальные заглушки в `src/lib/pipeline/`, см. `scripts/run-digest-stub.mjs`):

GitHub Actions по расписанию (cron) → news-scout → writer → cover-artist → page-builder → PR → обязательные проверки → авто-merge → Vercel.

- Объём: 3–5 статей за один прогон.
- Источники: минимум 2 независимых источника на тему; при расхождении данных между ними — автоматический поиск третьего источника; темы, не прошедшие отбор, фиксируются в журнал отбраковки.
- Обложка: при сбое генерации через Replicate используется fallback-обложка.
- Публикация: прямой push в `main` запрещён (см. раздел «Git»), поэтому публикация идёт через PR; авто-merge выполняется только после прохождения обязательных проверок.
- Имя файла статьи: `YYYY-MM-DD-<latin-slug>.md`, slug — латиница/транслит заголовка.
- Формат и стиль статей — см. раздел «Редполитика» выше (не дублируется).

### Критерии важности новости

Новость считается важной, если она реально может повлиять на работу финансового директора или решения компании и подходит хотя бы под один пункт:

1. Изменились налоги, ставки, лимиты, сроки, формы отчётности, штрафы или обязательные правила для бизнеса.
2. Вышло официальное решение ЦБ, ФНС, Минфина, Правительства или другого ведомства, которое влияет на деньги, расчёты, налоги, кредитование или отчётность.
3. Изменение может заметно повлиять на расходы, доходы, денежный поток, стоимость кредитов или финансовые риски компании.
4. Появилось новое требование или срок, из-за которого финансовому директору или бухгалтерии нужно что-то сделать.
5. Произошло крупное изменение в банковской, платёжной или финансовой системе, которое может затронуть работу компаний.

Не считать важными:
- рекламу и рекламные материалы;
- слухи и неподтверждённые сообщения;
- повтор одной и той же новости;
- мнение без новых фактов;
- новости отдельной компании, если они не имеют заметного значения для других компаний или финансового рынка.

## Git

- Ветка по умолчанию `main`.
- С фазы 08 PreToolUse-хук блокирует прямой push в `main`. Автоматика коммитит в ветку `digest/auto`, слияние в `main` — вручную по желанию.
- Запрещены `git push --force`, `git reset --hard`, `git commit --amend`.
- Коммиты не должны содержать footer-строк автоматической атрибуции (`Co-Authored-By`, `Generated-By`, `Signed-off-by` и т.п.), если пользователь явно не попросил об обратном.
